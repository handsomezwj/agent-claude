# IT 运维排障手册

## 概述
服务/服务器出问题时的排查顺序与常见错误速查。**只读原则：Agent 只做检查诊断，不执行删除、重启、杀进程等破坏性操作——需要人工确认后手动执行。**

## 排查顺序
1. **进程**：服务进程是否在跑（check_service）
2. **端口**：端口是否在监听
3. **日志**：日志里报了什么错（query_log，先搜 ERROR / WARN / CRITICAL）
4. **资源**：CPU / 内存 / 磁盘是否打满
5. **依赖**：数据库、上游服务、缓存是否正常

## 常见错误速查
| 日志关键字 | 含义 | 优先排查 |
|---|---|---|
| database connection pool exhausted | 数据库连接池打满 | DB 是否慢/挂、是否有连接泄漏，再考虑调大连接池 |
| out of memory / OOM | 内存不足 | 看进程内存趋势，排查内存泄漏 |
| Connection refused | 目标服务没起或端口不对 | 确认服务状态、端口号 |
| timeout | 上游响应超时 | 网络、上游服务性能 |

## 护栏
- **删除（rm/del）、杀进程（kill/taskkill）、重启（systemctl/service/reboot）一律拒绝**，需人工确认
- 日志只能读运维目录内的文件，`../` 越权路径直接拦截
- 回答要引用日志里的证据（第几行），拿不准就直说"日志里没有证据"，不编
